CityOS (Civitas AI)

An Autonomous Multi-Agent Decision Intelligence Platform for Smart Cities

CityOS ingests real-time weather, air quality, traffic, and citizen data, reasons over it with a goal-driven multi-agent runtime backed by a Neo4j + Qdrant knowledge graph and NVIDIA Nemotron models via OpenRouter, and surfaces explainable, human-approved decisions through a Decision Workspace dashboard — real data only, in English or Vietnamese.

Why This Project

City operators don't need another dashboard. They need a system that reasons.

Hanoi generates a constant stream of fast-moving, ambiguous signals — a sudden downpour, a spike in PM2.5, a cluster of citizen complaints, a crowd forming for an unplanned event. Individually, none of these signals says much. Together, read in real time by someone who has to decide whether to close a road or open a cooling station, they're exactly the kind of judgment call that's easy to get wrong — either by reacting too slowly, or by trusting an opaque system that can't explain itself when the decision turns out to matter.

CityOS is built around a different premise: an AI system that recommends action for real emergencies should never be a black box. Every agent in the pipeline — Traffic, Environment, Emergency, Citizen, Knowledge — cites structured evidence instead of asserting a conclusion. A rule-based Critic checks that evidence for sufficiency before anything reaches a human. And nothing ships without an operator's approval. The system's job is to make the reasoning behind a recommendation inspectable, not to replace the person accountable for it.

This project exists to demonstrate that a multi-agent architecture can do this in practice — not as a toy demo with fabricated metrics, but as a system running against real weather and air-quality feeds, a real knowledge graph, and a real (if simulated-scenario) approval workflow, end to end.

Architecture Overview

Four layers, one decision loop

The frontend never talks to an LLM directly, the agent runtimes never write to Postgres directly, and no agent calls an AI provider directly — each layer only knows about the one below it.

Frontend — Stitch Shell

React + TypeScript dashboard. Decision Workspace, Decision Sessions, City Intelligence, Knowledge Graph, Reports, Settings — real backend data only, English/Vietnamese.

FastAPI Backend

REST + WebSocket API. Routes goals/simulations to the agent runtimes, streams live progress, serves CityScore/AQI/decision-history reads.

Multi-Agent Runtime

v1 sequential pipeline + v2 event-driven Planner → Workers → Reflection → Decision, gated by human approval.

Knowledge + AI Gateway

Neo4j + Qdrant knowledge graph; NVIDIA Nemotron via OpenRouter behind a single gateway, Gemini fallback.

Data Layer

PostgreSQL (sensor readings, decisions, sessions) · Open-Meteo + OpenAQ (real per-district weather/AQI, refreshed every 15 minutes)
